# FolioPHP: agent instructions

## Repository
- This repo owns the reusable PHP 8.5 engine in `App/` and its entrypoint in `bootstrap.php`. Website content, templates, and deployment config belong in the consuming repo. Do not hard-code a particular website’s layout, languages, or routes.
- Keep the runtime free of third-party PHP dependencies. Composer metadata describes the package; bootstrap does not require a Composer autoloader or `vendor/`.

## Engine code
- Use `declare(strict_types=1);` in handwritten PHP logic, not in data files generated by `Store`. Follow existing patterns and extend existing classes before adding abstractions. Shared engine file I/O belongs in `App/Core/Store.php`.
- Preserve public template helpers, config semantics, and file formats unless the contract change is intentional and approved. Update the README when public behavior changes. Comments explain why, not what.
- Fail fast on missing or invalid required data. Optional template values and empty directory scans are valid. Validate request data at the boundary; don’t build file paths or headers directly from untrusted request data.

## Workflow and validation
- Before non-trivial changes, state the issue, root cause, proposed change, and net line delta; wait for approval. Typos and obvious one-liners can be fixed directly. Justify any net growth or new file.
- Lint changed PHP with `php -l` and run a focused check of the affected behavior. Skip runtime checks for docs or comments only. For HTTP checks, use a disposable copy of a consuming site linked to the engine checkout under test. For request-wide changes, check default-language, localized, nested, and missing routes; inspect output and server logs.
- For scaffolding changes, start with the affected file missing, verify the generated content, and confirm a second dev request leaves it unchanged. If write gating changed, verify that a pre-scaffolded site renders with `dev_mode` off without rewriting source files.
- Commit or push only when explicitly requested. Check the staged diff and remote. Publish engine changes before a consuming site updates its framework pin.
